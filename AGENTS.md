# Organic Framework: rules for agents

This repository holds the framework only: its documents (`docs/`), its packages (`bench/`), the lab (`lab/`) and the platform code (`bin/of`, tests). It holds no organization's data. Reports and research notes are kept by the team that builds OF, in its own repository.

Every organization that uses Organic Framework is an app with its own repository, which holds its registry, briefs and reports:
- the team that builds OF: `~/organic-framework-build` (structure keeper `of_architect`);
- for example, Acme: `~/acme/org` (structure keeper `acme_org`).

Each machine lists its organizations in `~/.config/of/orgs.yaml` ([`docs/registry.md`](docs/registry.md)).

## Language

- **Documents are in English only**: everything committed to this repository, including docs, reports, registries, briefs, code comments and commit messages.
- **Chat with the founder is in Russian.**

## Agent names

- An agent is named `<system>_<role>` after its position, for example `of_architect` or `storefront_operator`. A project is named `<system>_<task>`.
- A name matches `[a-z][a-z0-9_-]{0,31}` (herdr's agent-name rule): lowercase, no dots, at most 32 characters.
- Every position has exactly one canonical name. Older names live only as `aliases` in the registry.
- Every organization's registry is `registry/positions.yaml` in its own repository.

## No heavy local jobs on a laptop

- Light work only: reading, editing, small scripts, `git`, `herdr` CLI calls.
- Builds, `cargo`, `forge`, `docker`, test suites, long scans and other heavy jobs run on a remote machine or in CI, never locally.

## Framework and apps

- Framework material (the framework, the method, the platform) lives here.
- **App material lives in the app's repository.** Acme's material goes to `~/acme/org`, never to this repository. A framework document tells a lesson of "a user organization" and never names it, its people or its hosts; the check before each public export enforces this.
- **The OF team organizes; each organization operates** (founder, 2026-11-07: a user organization's tasks kept reaching the OF architect's session). The OF team designs the framework and, through each organization's structure keeper, how that organization is organized: positions, units, delegations, envelopes, goals, measures. It never runs an organization's work: its tasks, the founder's tasks and asks about that work, its secrets, its windows, its incidents.
  - When the founder raises an organization's operational matter in an OF session, the OF agent hands it to that organization's structure keeper (for example `acme_org` for Acme) in one message and tells him where it went.
  - The OF team takes from an organization only framework matters: a bug in `of`, a schema need, a missing capability. They come through its structure keeper, never straight from its unit positions.
  - An OF agent's end-of-turn summary names only the OF team's asks and organizing decisions.
- The registry schema lives here, in [`docs/registry.md`](docs/registry.md). It is an interface other positions read: tell `of_architect` before changing it.

## Working together

- **Guard and secrets rules live in [`docs/guard.md`](docs/guard.md)** (owner `of_server`): every rule, its reason and its test. A rule changes there first; the rules below that touch secrets are summaries.
- **Nobody waits unseen** (founder, 2026-11-05). Ask the founder anything only with `of ask "<question>" [--options "a|b"] [--blocking]`: a question that stays in your pane is invisible. **A question to the owner stands on its own**: what you need decided, why now, the options, and what each one leads to; `of ask` attaches your mandate and your last turns, but the question itself must be readable without them. At the end of every turn, declare where you are: `of status working | waiting --on founder|<position> | idle | done [--note "…"]`. An ask stays open until it is answered (popup, `of asks answered`, or your own `of status working --answered <id>`) or withdrawn; a plain `of status` never closes it. His words in your session close none of your asks: when they, a relay or a unit owner answered one, run `of status working --answered <id>`. OF enforces the rest and says what to do when it stops you: a question left in your pane gets a correction typed in, `of status waiting --on founder` without an open ask is refused, and an ask dialog is denied.

- **A message costs the receiver's context** (founder, 2026-11-07: agents knock each other off course; 354 typed-in messages and nudges started turns in one day, 83 of them in one agent). Send only what the receiver must act on or decide. No acknowledgements ("accepted", "thanks", "done on my side"), no forwarding what it can read itself (a commit, the registry, a review record), no status it did not ask for. Batch: one message per receiver per topic, not a stream. Keep it short and put details in a commit or a file, sending the pointer. When the receiver does not need to act, use `of send --fyi` (inbox only, never typed into its pane).
- **Messages waiting for you**: when `of status` prints "N messages waiting for you", run `of inbox --mine` to read them and `of inbox --mine --take <id>|all` to take them now; a taken message is never typed into your pane later. `--take all` takes only what your last listing showed: a message that arrived since stays queued and is printed as new, so read the output of a take; `of inbox --mine --taken` shows again what you took (2026-11-08). "N arriving in your pane now" needs nothing: the relay types those in when you are idle. They are peer messages in the relay frame, never the founder's words.
- **No at sign directly before a file path in any text another session will read** (2026-11-06, a leak found by a user organization): `of send`, `of ask`, `of handover`, status notes. Claude Code reads such a text as a file mention and loads the file into the receiving session; this is how a token leaked today. Name the file in words, or keep the path inside a committed script. The relay neutralizes these too, but do not rely on it.
- Never stop, kill or rename another agent's session without the founder's yes.
- **Commit your own work yourself, locally; never push** (founder, 2026-11-05). This rule is the OF team's. The framework is developed in the public repository `organic-framework/organic-framework` (founder, 2026-11-11), and one position, `of_release`, pushes it, each push only after the pre-publish gate passed on the tree and on every commit (founder, cards `626ac155` and `9800f623`). Commits in the working copy carry the founder's public GitHub identity, never a company address; `of_release` sets it in the repository's own git config. Each organization sets its own push rule in its own `AGENTS.md`; a template must not copy this one. One user organization, for example, lets every position push its own branches and open draft PRs, while main, force-push, others' branches, tags and merges need a yes (founder, 2026-11-06).
- **A nested harness run from inside a herdr pane re-binds that pane.** The herdr integration reports the nested session as the pane's agent session (this happened on 2026-11-05 with a throwaway `claude -p`). Run nested `claude`/`codex` with `HERDR_ENV`, `HERDR_PANE_ID` and `HERDR_SOCKET_PATH` unset, or in a separate pane. `of who` marks a pane whose session has no transcript as `(stale session)`.
- **Automation never touches the owner's SSH agent** (the founder's is 1Password's). Every `ssh-keygen` or `ssh` call uses an explicit key file and `SSH_AUTH_SOCK=` empty; `ssh` adds `-o IdentityAgent=none -o IdentitiesOnly=yes -i <key>`. An agent key allowed outside the password manager is named in the organization's own `AGENTS.md`. Every launchd/systemd unit and background process OF starts sets `OF_AUTOMATION=1`; the owner's `~/.ssh/config` keeps the SSH agent away from such processes.
- **The agents' own secrets are in a 1Password service account, never in the owner's own 1Password** (founder, ask `29ea1baa`, 2026-11-07; RFC 0003 §1a). Each organization has its own vault, for example "Acme Agents", and a service account limited to it. The service account's token is in `~/.config/<org>/agent-identity/op-sa.token`. Only committed scripts read it and call `op` with `OP_SERVICE_ACCOUNT_TOKEN` set; the guard denies a bare `op`, which would prompt the owner (docs/guard.md G9).
- **Kernel and process memory hold keys**: they are read only by a committed, reviewed script that prints no memory contents, and never leave the host (RFC 0002 §4.1). The guard denies the rest (docs/guard.md G7).
- Every agent commit and pull request ends with a `Position: <name>` trailer naming the author's canonical position name ([`docs/events.md`](docs/events.md), work records).
- Do not create positions yourself; propose them to `of_architect`.

## Asking the founder (or any human owner)

Founder, 2026-11-06: questions written as if to another agent, an evidence dump with no context, are useless to him. He reads an ask on a card in between other work, **without your context**. Write every `of ask` for a person who knows nothing about your last hour:

1. **The decision in one line.** It is a question he can answer, in Russian, in plain words: "Запускать ли обновление k8s до 1.36.6 сегодня в 10:00 UTC?"
2. **Why now.** Give the deadline and what happens if nobody answers: "Окно начинается через 40 минут; без ответа я его пропущу, и следующее — в четверг."
3. **Context in 2–4 sentences.** Which system, what happened, what you have already checked. Spell out every internal name or id the first time you use it.
4. **The options**, each with its consequence, risk and money cost, never a time estimate. Mark your recommendation and say why: `--options "да, запускать (рекомендую: …)|нет, перенести на четверг"`.
5. **The evidence goes after the text, never instead of it**: links to PRs, dashboards, log lines and file paths.

Rules:
- **No time estimates** (founder, 2026-11-11: "не озвучивал сроки ... в этом нет смысла"; 17 of his 49 open cards then carried durations). Never tell the owner how long something takes: his hands ("about 15 minutes"), preparation ("1–2 days"), a run or a build. A real deadline with its source stays, because it is a fact: a legal due date, a booked window, a limit's reset, a session's expiry, a meeting he named.
- **Every claim that drives work carries its basis** (2026-11-11, two incidents in one day: a paraphrase put a colleague on systems he does not keep, and a watcher's unconfirmed inference merged as a "compliance requirement"). A hand-over, a PR, a commit, a brief or a registry line that says something must be done names why: an owner's ask id, a source with the quote, evidence, or "inference, unconfirmed". Pass a basis on unchanged; never write an inference as a requirement (docs/handover.md §1.1).
- **The owner's decisions travel as ask ids, never retold** (2026-11-06, from a user organization's structure review). Write "the founder approved X (ask `a76abee5`)", not "the owner said yes in my session". The receiver checks the id with `of asks --all`. A retold approval carries no authority. In a registry, a brief or a diff, the owner's words are quoted verbatim with their date or ask id, never paraphrased (2026-11-11: a paraphrase put a colleague on systems he does not keep; docs/registry.md, People).
- **A founder's pause or decision covers only what his words name** (2026-11-09, from a user organization's lessons). A pause on the agents' mailbox also withdrew the 1Password vault task next to it, and that task then dropped unseen. Withdraw or pause only the item he named; anything next to it keeps or gets its own ask. Before calling a matter settled by an ask, check that its result exists.
- **One decision per ask.** If you have several, send several asks or number them.
- **Don't ask what you may decide yourself** within your mandate and grants. In a delegated unit, ask the unit owner first; the founder gets only escalations.
- **When you escalate or relay another position's question, rewrite it** in this form. Never forward it verbatim.
  A unit owner rewrites an ask OF escalated with `of ask --escalates <id>`; the note OF types in says how.
- Use `--tags` (prod_change:<systems>, money, security_incident, irreversible, window_go:<systems>). Use `--blocking` only when you really stop.
- **Work for the founder's own hands is a task, not a question** (founder, 2026-11-06): a key, a login, a token, a payment, a click in a UI. Use `of ask "<title>" --task "<the steps>" [--command "<what to paste>"]`; it sits on top of the popup under "Сделать тебе". An answer or a reply does not close it: when he says done, check the result (the new key works), then `of status working --done-task <id>`; if it is not there, `of status working --reopen-task <id> --note "what you still see"`. The pulse reminds him every 2 hours. A chat line or a note in your pane is not enough.
- **One task is one sitting of the founder's hands** (2026-11-07: QuickNode task 740d914b held "add the new token now" and "delete the old one after tonight's swap"; he did the first, it was checked, and the task still hung for him all day). A step that must wait for a signal, a window or another decision is its own task, filed when it can be done. A task that depends on a yes is filed after the yes. When the part he did checks out, close the task with `--done-task` the same turn.
- **A task that makes a secret says where it is run and where the value goes** (2026-11-07: a `setup-token` command from a task was run with `!` inside an agent's pane, which would have put the token into that agent's transcript). The steps say: run it in a plain terminal tab, never with `!` in an agent's session and never pasted into a chat; save the value with a silent read into a mode-600 file the steps name (`umask 077; read -rs T; printf %s "$T" > <file>`); a committed script (RFC 0002 §4.1) takes it from there. Never claim a tool saves the value to a file unless you checked it does.
- Use `--due <ISO time|+40m>` when the answer is needed by a time: the popup puts blocking asks and those due within 2 hours first, with a countdown; give a real deadline, not a wish.
- A bad ask: "evidence: kubectl get nodes … 22 Ready; window 10:00Z?". A good ask follows points 1–5 above.

## Platform code

- The `of` CLI is `bin/of`: Python 3 with PyYAML, over the herdr CLI. It reads the registries of the organizations listed in `~/.config/of/orgs.yaml`.
  - `of view list|apply <name>|add <name> --workspace W --tab T --layout main-left-60|grid --positions a,b|remove <name>`: pinned views (`~/.config/of/views.yaml`; `bin/of_views.py`), tabs the owner keeps in sight. The desk router never takes their positions onto the desk, `of apply` never moves or relabels them, and the listener restores a view when one of its agents was moved away.
  - `of conductor panel [--once] [--every 30]`: of_conductor's panel (`bin/of_conductor_panel.py`): the founder's open requests from the conductor's ledger (`~/.local/state/of/conductor/requests.yaml`, written only by of_conductor), each thread's live state from the records (hand-over events, answers, the owner's declared state and last turn, his cards), its last movement and a stuck flag, in Russian. A pinned view may hold such a pane: `panels: {name: command}` in `views.yaml` and `panel:<name>` in its `positions`; `of view apply` starts it and lays it out like an agent.
  - `of listen run|rebuild|status|install|uninstall`: the listener (RFC 0001 §5.1a; `bin/of_listen.py`), one local service (launchd `dev.organic-framework.listen`, `OF_AUTOMATION=1`) that follows the event store by a cursor per processor and keeps materialized views in the same store (`view_asks`, `view_ask_groups`, each row with its `view_version`); it bumps `views.seq` when a view changes. The pulse runs inside it as a timer every 5 minutes (`of pulse install` installs the listener and removes the old launchd job `dev.organic-framework.pulse`). Views are caches, rebuilt by replay; without the listener the CLI computes from the log (the earlier rule "no daemon" is replaced by this).
  - `of apply [--dry-run]`: bind each position to its live holder by `holder.session`, set the herdr agent name, the pane tokens `system`, `role`, `summary` (source `of:registry`), the pane label `■ name ■`, the tab label (role) and the workspace label (organization; never the desk); for an organization with `units:`, one workspace per unit (`<short>·<unit>`) with a tab per system, moving misplaced panes; report positions without a live holder and agents without a position.
  - `of who [--json] [--long]`: one table; agents that need the owner first (herdr `blocked`/`done`, or `waiting_on: owner`), parked and finished positions last. A position held on another machine of its organization shows `remote:<state>` with the machine, the person and the presence's age (`GET /v1/presence`; `bin/of_presence.py`).
  - **Only the machine that holds a position acts on it** (docs/server-several-machines.md §4.3, 2026-11-11). The pulse, hand-over offers and expiry, ask corrections, the desk and the asks reconcile type into a pane, and record events about a position (nudges, stalls, escalations, holder changes), only for positions this machine holds; a position held on another machine (its presence) is left to that machine, which sees the same state through the coordination feed. An event two machines may both write about one fact (an escalation, its founder copy, an expiry, a mandate snapshot) has a fixed id (`of_events.stable_id`), so it is kept once. Test: `tests/test_several_machines.py`.
  - `of spawn <position> [--config-dir D] [--cwd DIR] [--model M] [--dry-run]`: start a position's Claude Code session in a new pane of its place, on the account with the most headroom among those that trust its system's folder, in that folder, and type its brief declared as an injection (`bin/of_spawn.py`). Trust is read as Claude Code reads it: the folder, or a trusted folder above it up to its git repository's root, never above the root (2026-11-09). It writes the position's credential deny rules from the catalogue and its tool profile (`allowedMcpServers`, `enabledPlugins`, `--mcp-config`; docs/tools.md §4) into the session's own settings (docs/registry.md, Credentials); `of resume-command` does the same. It stops and files a task for the owner (in the language of `~/.config/of/owner.yaml`, English by default) when no account trusts the folder or the account has not accepted Claude Code's Bypass Permissions warning, refuses a position with a live holder or held by a person, and prints the `holder.session` line for the structure keeper. Whoever spawns without it declares the brief with `of event injected_prompt`.
  - `of fit replay [--sender P] [--receiver P] [--since ISO] [--out F]`: the mandate-fit judge (`bin/of_fit.py`, RFC 0001 §5.7): a small model reads the messages one position sent another and says whether the work belongs to the receiver, to another position (named) or to none; replay records nothing. Scored in `lab/scenarios/lab-fit-v0` (synthetic and real labelled cases).
  - `of delegate "<task>" [--from P]`: before a manager hands out work, a small model reads every mandate of its organization and names the positions that should do it, says when none does (grow a mandate or add a position, for the structure keeper) and where two mandates overlap (`bin/of_fit.py`; records nothing). A manager runs it before giving a position new work (founder, 2026-11-10: work went to the wrong role because nobody checked).
  - `of resume-command <session>`: the line that resumes a Claude session as it ran: the account holding its newest transcript, its model and effort, its permission mode (`bin/of_resume.py`). herdr resumes agents after its own restart as a bare `claude --resume <id>`; the `claude` function in `bin/of-shell.zsh`, sourced from `~/.zshrc`, runs this line instead in a herdr pane (2026-11-10: 38 sessions came back on a spent account in auto mode).
  - `of loop hypothesis|run|decision|show <work>`: a work's development loop (RFC 0005; `bin/of_loop.py`): a hypothesis before its test (`--predict`, `--cost`, `--voi`), a run on a rung of the work's ladder when it ends (`--rung`, `--hypothesis`, `--result`, `--evidence`), a decision (keep, drop, park, step_up, step_back, change_objective with `--money`), and the register, the next hypothesis first by value of information per runner-hour.
  - `of go <name>`: focus by canonical name, alias, role, pane id or session id; ambiguous names are rejected.
  - `of desk [show|case|pin|unpin|put|on|off|run|once]`: the desk (herdr workspace `desk`, N slots in splits) shows the founder's current case ([`docs/desk.md`](docs/desk.md); `bin/of_desk.py`, `bin/of_case.py`). After he types into a pane, the listener has a small model name his case and its agents from his prompts, the answers to him and the agents' messages (`of.case_inferred`; `of desk case` shows it). The router brings the case's agents in and replaces only what it placed itself; it never moves what he put there, the focused pane or an agent he typed to in the last 15 minutes, and never brings an agent in because it finished a turn or has an open ask. An agent off the desk waiting in a dialog gets a notification. Settings: `~/.config/of/desk.yaml`; state and log: `~/.local/state/of/`.
  - `of corrections [list|judge|digest]` (RFC 0006 §2.4; `bin/of_corrections.py`): the founder's corrections as records. After he types into a position's pane, the listener has a small model judge whether his words correct the agent, and records the rule, its kind and the earlier correction it repeats (`of.founder_correction`). Once a day (from 05:00 UTC) each organization's structure keeper gets one `--fyi` digest from `of_platform`; the keeper decides where each rule goes (the brief, a rules file, or nowhere). Nothing is written into a brief automatically. A position's memory directory (`~/.local/state/of/memory/…`, `bin/of_memory.py`) is used by `of spawn` once `capacity.yaml` has `position_memory: true`; an index past 180 lines or 22,000 bytes is named to its keeper at session start, once a day.
  - **Disk** (`bin/of_scratch.py`, docs/storage.md "Disk and retention"): the pulse sizes each live session's scratch folder at most every 30 minutes, tells a position once when its folder passes 3 GiB, lists a folder past 6 GiB for the guard to refuse new writes into it until it is back under 3 GiB, and files one founder card when free disk falls under 20 GiB, closing it itself above 25 GiB. It never deletes a scratch folder.
  - `of asks [--all] [--json]`: the owner's queue of open asks, oldest first, projected from the event log (read-only; `bin/of_asks.py`).
  - `of ask [--blocking] [--due <ISO|+40m>] [--task "<steps>" [--command …]]`, `of status [--answered|--done-task|--reopen-task <id>]`, `of pulse [install|uninstall] [--no-nudge]`: declared questions and states, and the 5-minute pulse (`bin/of_pulse.py`; `of_pulse.project()` is the one model of who waits on the founder, who waits on whom and who stalled, used by `of who`, `of pulse` and Studio). `of asks` groups similar questions from several agents into one item; `of asks answered <id>` closes it.
  - `of registry check`: validate every listed registry (names, duplicates, enum values, YAML slips, units, delegations, `works:`); exit 1 on problems. Run it after every registry edit.
  - `of hook <HookEvent>`: the Claude Code collector (`bin/of_hook.py`), with the guard's critical denies in `bin/of_guard.py` (owned by `of_server` from 2026-11-07); `of event injected_prompt|state_declared`: events declared by tools and supervisors.
  - `of archive`, `of ingest <file>`, `of import`, `of ship`, `of db stats`: the trace store ([`docs/storage.md`](docs/storage.md)). Raw copies and the local SQLite spool live in `~/.local/state/of/`; `of ship` sends batches to the central ClickHouse (localhost:18123, database `of_tenant_<tenant>`).
  - `of invite`, `of enroll <server> --code C --org X`, `of consent`, `of shipped`: joining organizations on a server, consent per organization (typed always, raw opt-in), and what has left this machine. `orgs.yaml` `server:` per organization; `of ship` routes on the client and sends content to its source organization's server, and reduced copies (shape, publication) to another organization's server only when it is a different server.
  - `of issues [list]`, `of issues label <id> true_positive|false_positive|true_but_not_now|wrong_remedy [--note]`: the diagnosed issues (of_studio's `of model issues`) and the owner's label, `of.issue_labelled`.
  - `of handover propose <position> "title" --done-when "…" [--verify P] [--blocking] [--systems …]`, `of handover accept|decline|block|deliver|verify|reject|close|return|withdraw <id>`, `of handover [list]`: hand-overs between positions as events ([`docs/handover.md`](docs/handover.md); `bin/of_handover.py`); `of pulse` offers them into the receiver's idle pane, nudges after the response window and expires them.
  - `of diff check|propose|apply <file|id>` (`propose --ask "…"`: the owner's question in Russian, standing on its own, required for tiers medium and high; the diff file stays English), `of diff approve <id>` (the owner, in a terminal), `of diff list`: structural diffs ([`docs/handover.md`](docs/handover.md) §3; `bin/of_diff.py`). v1 applies spawn, mandate_rewrite and swap_holder as narrow text edits to the organization's registry and briefs, comments kept; medium and high tiers need the owner's approval of the exact content; the structure keeper commits.
  - `of send <position|org:position> "text" [--reply-to M] [--grant G] [--fyi|--urgent]`, `of relay run|on|off`, `of inbox`, `of inbox --mine [--take ID|all] [--from P]` (the calling agent's own queue on the server; `--from` only names the position when the registry cannot tell, and the session must hold it): messages between positions on any machine through each organization's server (`bin/of_relay_client.py`; the server side is `bin/of_server_relay.py`). The relay publishes presence, delivers into the agent's pane through herdr once it is idle (declared as an injected prompt), and keeps messages to positions held by people in `of inbox`. It types at most one prompt per receiver per 15 minutes, joining what is queued; `--urgent` bypasses that, and `--fyi` is never typed in (the receiver reads it with `of inbox --mine` when it chooses). `of pulse` nudges a waited-on peer only when it is idle, backing off per waiting pair (the first nudge, then 30 minutes, 2 hours, and once a day after that), never again before it has read the last nudge, never with the same text while it is unanswered, never after the peer answered the waiter within the wait (any message to it, `of send` included, or `of asks answered` on its ask), and never while the peer itself waits on the founder.
  - `of server run|enroll-machine|revoke|status`: of-server, the sync server in front of ClickHouse ([`docs/server.md`](docs/server.md); `bin/of_server.py`, client `bin/of_client.py`, routing `bin/of_route.py`). On this Mac it runs under launchd `dev.organic-framework.server` on `127.0.0.1:18200`; `of ship` posts batches to it.
  - `of init <org>`, `of hooks install|uninstall`: the quickstart and the recorder hooks (`bin/of_init.py`); see README.md.
- of-server plugins (storage, buffer, blobs, identity) live in `bin/of_plugins.py`; profiles choose them in `~/.config/of/server.yaml`.
  - `of derive [--session S]`: typed events derived from ingested history (gap #0; `bin/of_derive.py`), with the classifiers shared with the live collector (`bin/of_classify.py`, including the pinned baseline version `fa-2026-11-05`). `of import` runs it at the end.
  - `of model [summary|positions|systems|dsm|dmm|coverage|position-dsm|measures|snapshot|gate|works]`, `of works [--org O|--all] [--json]` (= `of model works`) and `of studio [--file PATH]`: owned by `of_studio` (`bin/of_studio_cli.py`, `of_model.py`, `of_measures.py`, `of_studio.py`, the run of `of_diagnose.py`); the anti-pattern rules in `bin/of_diagnose_rules.py` are `of_field-analyst`'s (2026-11-07); `bin/of` only dispatches them.
  - `of capacity status [--fresh|--no-probe] [--json]`: model limits per Claude account (config dir) and which positions run on each, from a minimal Haiku probe at most every 30 minutes, written as `of.capacity_snapshot`. `of capacity plan`: who to move where, in which order. `of capacity balance [--dry-run]`: spend first the capacity that expires first (also run by `of pulse` when `~/.config/of/capacity.yaml` has `auto: true`). `of capacity move <position> --to <config-dir> [--dry-run] [--allow-shells]`: move a live holder to another account between turns, in the same pane, with its context and memory (`of.holder_changed`); `--model M [--reason R]` restarts it on another model the same way, on its own account unless `--to` is given. `of capacity resume <position> --session S --to <config-dir> --pane P`: finish a move whose resume never started, with a declared note (nothing is typed into a pane undeclared). `of capacity creds [--adopt …]`, `of capacity vault`, `of capacity mint <config-dir>|--all-due`: the credential broker's inventory (fingerprints only), its 1Password service-account vault, and minting setup-tokens checked against the account (docs/capacity.md, "Credential broker"). `of capacity memory [<position>] [--from-transcripts] [--report] [--dry-run]`: seed each position's own memory directory from the accounts' folder memories (RFC 0006 §2.2; `--from-transcripts` attributes files with no `originSessionId` by their writers, `--report` lists the rest for each structure keeper); moves and resumes start on it once `capacity.yaml` has `position_memory: true`. `of capacity reboot prepare|restore|status [--only a,b] [--dry-run]`: before a restart of the Mac, record every live session and keep `/private/tmp` by hard links; after it, put the files back and resume every session on its account with a note of what died (production first). `of capacity babysit <position|session>`: what a session spends on runner commands and monitor-woken turns, by model, with the estimate for a small-context babysitter (RFC 0005 step 5). `of pulse` asks the owner once per account and reset when a position's account passes 90% of its week or 95% of its 5 hours. `bin/of_capacity.py`, [`docs/capacity.md`](docs/capacity.md); owned by `of_capacity`.
  - `of import github --org ORG --since DATE`: every merged PR as `of.work_record` (`bin/of_github.py`), systems by changed paths. `of import git --org ORG|all [--since DATE]`: every commit on `main` of the organization's checkouts (orgs.yaml `paths`) as `of.work_record {source: git, unit: commit}`, its position from the message's `Position:` line, for an organization that commits locally and never pushes; `--org all` takes the organizations whose systems name no GitHub repository. The listener runs both every 30 minutes.
- `bin/of_events.py` appends to the event log ([`docs/events.md`](docs/events.md)); `bin/of_desk.py` is the router.
- Tests: `python3 -m unittest discover -s tests -t .` (pure logic, no herdr calls). `tests/isolate.py` runs first for the whole run: no user or system git config (no commit signing through the founder's 1Password), no SSH agent, `OF_AUTOMATION=1`, and a temporary `HOME` with an empty organization list; `tests/test_0_isolation.py` fails loudly if any of it is missing. A git call in a test also passes `-c commit.gpgsign=false -c tag.gpgsign=false` (2026-11-07: test commits signed through 1Password).
