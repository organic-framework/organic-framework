# The guard: every rule, its reason and its test

Owner: `of_server` (trust and messaging, since 2026-11-07). This document is the one place for the rules that keep secrets out of an agent's context and out of anything that leaves a machine. `AGENTS.md`, RFC 0002 and RFC 0003 point here.

Every rule has:
- an id, so a test, a deny reason or a review can name it;
- its reason: the incident or decision, with its date;
- the test that holds it.

A rule without a test is listed under [Gaps](#gaps) until it has one.

## How the layers fit

An agent can reach a secret through five doors. Each door has its own layer.

| Layer | Door | Where | Installed by |
|---|---|---|---|
| N. Native deny rules | the harness reads a file (Read tool, an `@` mention resolved through Read) | Claude Code `permissions.deny` | `of hooks install --deny-secrets` (`bin/of_init.py`) |
| G. The guard | a tool call the agent makes (Bash, Read, Grep, Edit, Write…) | `PreToolUse` hook, `critical_deny` | `of hooks install --guard` |
| M. The mention guard | a prompt that names a secret file as an `@` mention | `UserPromptSubmit` hook | `of hooks install --deny-secrets` |
| R. The relay | text OF types into a pane (relay messages, nudges, offers, the popup's answers) | `herdr_deliver` in `bin/of_relay_client.py` | always on |
| K. Masking | anything that leaves the machine or is stored | `bin/of_mask.py` (server), `of_store.redact_keys` (ingest), `of redact` | always on |

The guard's rules are `bin/of_guard.py` (`critical_deny`, `prompt_secret_mention`), extracted from `bin/of_hook.py` in `3368d86` and owned by `of_server` since hand-over `7d3cee0b` (2026-11-07). The hook's glue stays with `of_platform`: `of_hook._guard` and `_mention_guard` turn the rules' answers into the hook output and `of.mandate_check`, and import exactly `critical_deny`, `prompt_secret_mention` and `_WARNINGS`. A change to those signatures is announced to `of_platform`. The hook reads `of_guard.py` from disk on every call, so a rule change needs no restart.

**The principle** (`of_architect`, 2026-11-06, after three leaks that day):
- a secret **value** never reaches the transcript (stdout, stderr, the command text);
- a secret **file** never leaves its place;
- names are not secrets;
- a credential that a program reads without showing it is not a leak;
- the guard denies what will **execute or be read as data**, never prose a command only carries (an `of send` text, `git commit -m`, a heredoc written to a file).

## How a rule changes

- **Replay first.** A new deny rule is replayed over at least 21 days of recorded Bash commands before it denies: `bin/of_guard_replay.py run --days 21 --out before.json`, change the rule, `run` again, then `compare before.json after.json`. It never prints a command, only the reasons and a masked first word. The commit message gives the count of new and removed denies, as in `b94d92e`, `0ae539c` and `484aa15`. On 2026-11-07: 136,702 distinct commands, 1,555 denied.
- **Warn before breaking a live flow.** A rule that would deny a flow in use warns first: it allows the call, writes `of.mandate_check {verdict: warn}` and gives the agent a one-line note. It denies once the flow has moved. The bare-`op` rule (G9) did this from `2692d6b` to `9bb1e06`.
- **A false positive over a miss** where the guard cannot tell. Interpreter code is matched by its string literals. The agent writes such code to a file with the Edit tool first.
- **Every deny names what it matched** (`of_architect`, 2026-11-06). The reason starts with "Organic Framework critical deny:".
- **Every deny is recorded** as `of.mandate_check {verdict: critical, decision: deny, mode: enforce}` with the masked subject. The decision is written to stdout before recording, so a broken store never turns a deny into an allow.
- **The guard never fails open silently** (`2a76593`, 2026-11-06, `lab-secrets-v0` Run 2). The hook runs under the absolute interpreter it was installed with and decides before importing PyYAML. A parse failure falls back to the stricter text match outside quotes; it does not allow.

## O. Organization rules (2026-11-09)

**Where they live.** An organization's rules are **deny grants** in its `registry/grants.yaml`, signed by the tenant (`of_architect`'s decision, docs/registry.md "Organization rules", `4a14716`). The positions they limit cannot edit them: an edit breaks the signature. A grant becomes a rule when it has:
- `subject: "*"` with a signed `except` list, or one position as its subject;
- `effect: deny`;
- `scope.kubectl` with the O1 keys;
- `note`: the reason the agent sees.

A non-critical deny **warns** and a critical deny **denies**. A rule starts in warn and moves to deny when the tenant issues a new grant and revokes the old one, after the replay shows that the live flows have moved. A session with no position gets no exception.

## Known limits

From RFC 0002 §4.1. They are written up, not closed:
- an **unknown wrapper** (`$W "…"`, a project's `vsb.sh '…'`) or **indirection** (`cat $(echo .env)`, a variable holding the path) hides a read;
- a heredoc written to a file through a doubly nested `kubectl exec` → `ssh` can be re-split and wrongly flagged (an accepted false positive);
- interpreter code is matched by its literals, so an edited test string naming a secret path is denied;
- OF's own holder detection runs `ps eww -o command=` in a subprocess, not as a tool call, so the guard never sees it and needs no exemption;
- G1.8 matches by the path's `.config/<dir>/` part: after `cd ~/.config/acme/x`, `cat clickhouse-password` names the file alone and passes (the G1.7 suffix classes are matched anywhere);
- G14 follows a variable only when it is set on the same command line, and walks at most 5,000 files of a directory read recursively; a path built at run time (`$(…)`, a loop variable) is not seen;
- G16 sees a command line and a tool call: a script kept in a file that mails or posts (`python3 send.py`), a connector that sends a draft by its id, an address held in an environment variable, or an authority missing from the lists is not seen;
- every agent runs as the same user, so a file's mode keeps no position from another's credentials; the guard stops a command line, not a process that wants the file. - **A grep, sed, awk or jq pattern counts as a file** for the secret rule (G5); kept on purpose (`of_architect`), because such patterns often print secrets (a BGP password grep, jq `.token`). The memory rule skips the pattern (`_PATTERN_FIRST`). Changing G5 would remove 33 old denies.
